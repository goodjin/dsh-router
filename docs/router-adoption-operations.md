# Router 收编：读取成本、诊断与运行边界（v1.4）

核对日期：2026-11-08。宿主格式依据本机 DSH 0.2.2-rc.1（会话日志 v4）。本说明
描述 v1.4 语义下的实现：Router 会话全部独立（不去重、不归档、不跳转、不复用），
收编扫描只负责把 picker 自建的 Router 预设会话登记进 `ui.routerSessions` 并幂等
补发身份卡；判定源是已评审的受限读取器 + 持久化增量索引（router-header-index
迁移），不再走宿主 `readSession()` 整日志重放。

## 行为与成本（2026-11-07 OOM 现场之后的设计）

- 收编判定不调用宿主 `readSession()`，也不做整语料 `stat/list/open` 兜底。冷盘
  小日志只按有界 stable-EOF 扫描取「最终预设组合」；live 会话经宿主
  `sessionProjections` 的 `agentPreset` 投影与 `agent-preset/selected` 事件直达
  判定（零盘读）。
- `/router/state` 每 2.5 秒轮询一次：收编每轮只消费索引的**资格授予**
  （`claimRouterGrants`：只领取**未领取**的新授予；消费方自己正在退避重试的
  那些留在"已领取"面，由到期堆驱动，不再参与每轮枚举）与**定点**磁盘事实核验
  （`verifyDiskFacts`：一次只点一个候选名）。稳态轮次零副作用——不再出现旧现场
  「每轮全量重扫 = 200%+ CPU、几十分钟堆满 4 GB JS 堆」；稳态轮次也**不再遍历
  宿主工作区/会话成员**（成员定位走索引的增量定位表，成员/归档的权威核验只在
  副作用边界定点进行）。
- 延期重试与新授予**分开枚举**（review I7 round 2/3）：延期队列带**到期最小堆**
  ——堆顶未到期就是"本轮没有到期重试"（O(1) 空过，不复制全量快照、不构造
  全量 skip 集合）；新授予只从未领取面领取（枚举到单轮预算即止）。两条路受
  **同一个单轮预算**约束：检查量与维护量一起封顶，不随积压线性增长。
- **单轮预算同时约束维护与副作用**（review I7 round 3）：每弹出一个堆条目
  （无论有效还是失效/墓碑）都扣 1，每处理一个候选也扣 1 → 一轮不可能清空整个
  失效积压；"预算耗尽"（还有工作但本轮用完）与"没有到期项"在健康诊断里是
  两个不同的计数。
- **来源明确交替**（review I7 round 3）：轮转位决定下一份工作先取"到期重试"
  还是"新授予"，每完成一步翻转且**跨轮保留**（budget=1 也交替）→ 长期失败的
  积压不会把新授予饿死。
- **授予所有权**（review I7 round 3）：消费方**逐条领取→处理**（不批量预领），
  告警面抛错不会打断恢复路径；未 ack 的授予要么在未领取面、要么在延期队列里
  有一个明确的所有者——不存在"已领取但无主"的孤儿。
- 索引自带护栏（沿用已评审机制）：首次 bootstrap 有界分批（全局每批最多 10
  次尝试，失败也占预算）、瞬态失败冷却 10 分钟、后台推进约每 250ms 一批、
  低频目录对账默认 60 秒、判定按 root+preset+版本持久化（指纹未变直接复用）、
  单飞 + 安全 dispose（在途读取收尾、状态冲刷完成后才真正消停）。
- 收编侧护栏：每轮预算（默认 10 次异步副作用）、单飞、失败候选进**可恢复的
  延期队列**（指数退避，默认基数 2 秒、封顶 60 秒；**不再有"连续失败 N 次就
  永久放弃"**——短暂故障恢复后候选仍会被收编）、延期与新授予轮转交错（失败的
  头部不反复占用预算，后来者公平前进）、身份卡投递幂等（进程内 delivered 集合
  + 桥侧已发标记 + requestId 去重）。
- 资格记账（可靠消费）：资格"当前确实成立"才有授予；载入缓存未核指纹
  （`verdictOf` = pending）、判定为 unknown/nonrouter 的会话**不在**待消费面，
  不会被提前消费掉；判定翻到别的值再翻回来会发**新一代**授予（资格代数 +1），
  不会被旧基线永久漏掉。消费方**成功才 ack**。
- 异步安全：每个副作用启动前都重新核对「当前仍是 router 判定 + 仍在**目标**
  工作区成员里 + 未被宿主归档 + 磁盘事实仍新鲜 + 生命周期代际未变」；登记等待
  之后**再核一次磁盘事实**并复查同一组条件。等待期间翻面/离开/归档/撤销的候选
  只延期自身，不按 stale 计划登记或投递。单个候选失败（IO 超时/拒绝/异常）不
  阻断同工作区邻居。
- live 生命周期：宿主 `session/created` / `session/event` / `session/disposed`
  三个事件共用同一生命周期 token（已核实：当前宿主在三处传的是**同一个**
  Session 实例）。会话**离开 live store**（含发布回滚）时撤销它的 live 权威
  代际 → 进入受控冷重判/unknown（离开 live 后不再有投影事件维护的旧事实不得
  继续授权）；**旧实例的 disposed 不清新实例**。

### 默认扫描上限（冷日志 stable-EOF）

| 项目 | 上限 |
| --- | --- |
| 文件输入（压缩侧或明文） | 256 KiB，允许最多 1 字节探测是否超限 |
| 总解压输出 | 1 MiB |
| 事件行数 | 4096 |
| 单行 | 64 KiB |
| 单次读取生命周期 | 2 秒 |

超时让调用方及时返回；无法立即取消的底层 IO 仍占有限额度，直到真实完成及清理
后才归还。种子（seeded/fork）会话沿用排除规则（nonrouter）。

## 明确的功能限制

旧格式（v3-）、未来格式、超限、损坏、截断、存在歧义或读期间变化的日志保持
`unknown`——**只跳过该候选自身**，不阻断同工作区其他已确认 Router 的登记与
投递（v1.4 语义：unknown 不再有「挡住整个工作区」的效力）。表头不是最终预设
的可靠证明；首次 turn 也不是安全停止边界；本实现不使用这两类快捷判据。

冷文件变化有默认 60 秒发现延迟（低频对账）；跨进程文件写入与 registry 动作
没有事务级原子性保证。live 会话读不到权威投影值时保守判 `unknown`，等
`agent-preset/selected` 事件到达再前进。

会话**先创建、后挂进工作区**（picker 自建后延迟 attach）时，候选会留在延期
队列里等成员定位表刷新（低频对账，默认 60 秒）或成员失效刷新；这期间它
**不会被丢弃**，条件成立后仍会被收编。宿主归档的会话不会被登记或投卡（归档
事实由定点权威核验给出）；本实现不做任何自动归档/撤销动作。

### 已知的批量成本（如实记录，未弱化授权核验）

同一个工作区里若有大量已确认的 Router 会话，**每个候选**的定点成员/归档核验
都要读一遍该工作区的成员集合（`verifyTargets` 为定点权威查询重建成员集），
因此成员元素读取量按 **候选数 × 该工作区的成员数** 增长：实测 1000 个已确认
Router 同处一个 1000 成员的工作区时，一轮收编（1000 个候选）约 1,000,000 次
成员元素读取。这是**每个副作用都要拿到当前权威成员事实**的代价，不是可以
悄悄缓存掉的旧值（跨 await 缓存旧成员会让归档/移动判断失效）。稳态轮次
（无待消费授予、无到期重试）不读成员数组。

## 自报状态（GET /router/health）

使用现有宿主准入方式访问（需插件已启用）。接口不触发任何盘 IO，返回索引计数
与 `adoption` 段：

| 字段 | 含义 |
| --- | --- |
| `bootstrap.initialDone` / `lastReconcileAt` / `lastReconcileError` | 目录发现是否已跑、最近对账及错误 |
| `queueLength` / `failures` | 索引待处理与失败冷却计数 |
| `entries.router` / `nonrouter` / `unknown` / `byEvidence` | 当前判定分布与证据来源（stable-eof / 种子表头 / live） |
| `header.attempts` / `cacheReused` / 字节计数 | 实际头读取与复用成本（含失败消耗） |
| `scan.attempts` / `finals` / `caps` / `unstable` | 小日志扫描结果 |
| `adoption.rounds` / `registered` / `delivered` | 收编轮次与成功登记/投递计数 |
| `adoption.deferred` / `nextRetryAt` / `deferredReasons` | **可恢复**的延期候选数、下次可试时刻与延期原因分布（失败不再被永久丢弃） |
| `adoption.maintenance` / `budgetExhausted` | 维护消耗（清理失效/墓碑延期项）与**预算耗尽**的轮数（与"没有到期项"区分） |
| `adoption.retryQueue` / `verifyRejected` / `staleSkipped` / `retriesDropped` / `errors` | 队列长度（= deferred）与各类跳过/失败计数（`retriesDropped` 自 v1.4 起恒为 0） |
| `grant.pending` / `grant.claimed` / `grant.eligible` / `grant.visits` | 索引侧未领取授予数、已领取未 ack 数、当前成立的资格数与累计授予面访问次数（成本口径） |
| `adoption.inflight` | 是否有进行中的收编轮（单飞可见） |

诊断不返回会话正文、标题或路径。`entries.unknown` 不为零不是故障；把
`initialDone` 当作全历史覆盖同样不成立。

## 状态与部署纪律

判定索引保存在插件 dataDir 下 `session-index.json`（新文件名，不复用旧去重器
的 `dedup-index.json` 语义；旧文件不迁移也不自动删除），按 schema、会话根和
preset 隔离，载入缓存未经指纹核对前不授权任何副作用。

源码与四个宿主自包含入口产物（`dist/entry.js` 等）+ 浏览器产物（`lib/client.js`）
必须一起提交；部署前跑 typecheck、全套测试、build、二次构建字节比对，以及仅
跟踪文件的干净安装加载测试（`tests/tracked-install.spec.ts`）。离线门禁不能替代
真实桌面验证。

本任务不自动改 profile 的 disabled 覆盖、不合并主干、不推送、不重启桌面；启用
与重启由用户决定。首次启用后观察上述诊断、CPU/内存趋势与真实收编行为；异常时
保留禁用配置定位，不以反复重启代替排查。
