# dsh-router v1.2 实施计划（失控防护层）

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task.

**Goal:** 落地 v1.2 规格：故障分类器、全局熔断器、派发预算、事件驱动结果判定、通知卡与用户控制、提示词/记忆增补；v1.1 行为零回退。

**Architecture:** 宿主侧新增 `src/host/guard/`（breaker/budgets/adjudicator），挂进 core 的派发与状态观察路径；客户端新增统一通知卡与紧急暂停；先行验证 turn-end 触发源与根会话中断 API。

**Spec:** `docs/superpowers/specs/2026-11-07-router-v1.2-design.md`

## Global Constraints（继承 v1.1 全部；增量）

- 防护状态持久化于 dataDir（guard-state.json），宿主重启恢复冻结态。
- 预算按「轮次」近似「用户消息」边界（ask_user 的回答本身开启新轮，自然重计）——实现与测试都按轮语义。
- 所有新工具/路由输出过 lossless 门禁；新预设子行过 validateRowSpec（本版预期不动 patch 行；若动必跑双核查）。
- 判定用 llm 通道复用记忆摘要的 provider/model 配置链。

## Review Focus

1. 熔断误报代价：主管合法并行拆解不得被条件 b 冻结（创建≥10 零完成才触发，测试钉住 9 个不冻）。
2. waiting-user 豁免：有已认领待答问题的任务，轮次结束绝不触发判定。
3. 判定幂等：同一任务同一轮只提醒一次；提醒轮与判定轮不得重复触发。
4. 预算误伤：正常「一条消息一任务」路径零感知；第二轮派发被拒的错误信息必须指明 ask_user 出路。
5. 紧急暂停原子性：冻结+中断任一失败不静默（汇总卡如实报失败项）。

## Part B：宿主防护（TDD）

### Task B1: 故障分类器 + 全局熔断器

**Files:** Create `src/host/guard/breaker.ts`、`src/host/guard/classify.ts`；Modify `src/host/core.ts`（派发失败路径分类并上报、dispatch/createWorkerType 前检查冻结）、`src/host/root-config.ts`（窗口/阈值可配）、`src/entry.ts`（guard-state 持久化装配）；Test `tests/guard-breaker.spec.ts`。

**Interfaces:** `classifyDispatchFailure(err): { class:'infra'|'task'; detail }`（infra=会话创建/挂载/投递失败——bridge 层打标；task=模板/依赖/角色/预算类拒绝）；`class CircuitBreaker { recordFailure(e {taskId,at,class}); recordCreation(taskId,at); recordCompletion(taskId,at); state(): {frozen,reason,frozenAt,counts}; freeze(reason); unfreeze() }`（窗 10min；infra≥3 或 创建≥10 零完成；持久化恢复；completion 清创建计数基准）；冻结时 dispatch_task/create_worker_type 抛 `{code:'dispatch-frozen', reason}`，错误信息含「停止重试、向用户报告」。

- [ ] 测试先红：infra×3 冻结、task 失败不冻、9 创建零完成不冻/10 冻、完成后计数清除、持久化往返、unfreeze。
- [ ] 实现绿 → 门禁 → commit `feat(guard): failure classifier and circuit breaker`。

### Task B2: 派发预算

**Files:** Create `src/host/guard/budgets.ts`；Modify `src/host/core.ts`（派发/问答路径挂预算）、`src/host/bridge/questions.ts`（Router 会话的提问预算认领层强制）；Test `tests/guard-budgets.spec.ts`。

**Interfaces:** `class DispatchBudgets { onTurnStart(sessionId): void; tryConsumeTaskDispatch(sessionId): {ok}|{ok:false,code:'per-turn-task-budget'}; tryConsumeQuestionBatch(sessionId): 同形; recordDispatchFailure(sessionId): void; recordDispatchSuccess(sessionId): void; supervisorFrozen(sessionId): boolean }`——轮开始清零（bridge watchStatus 的 running→true 即新轮）；Router 每轮 1 任务 + 1 批提问（第二批在认领层自动回「请合并为一批重问」）；主管连续失败 3 次冻结（成功/新轮解除），错误码 `supervisor-failure-budget` 指明 report_blocker 出路。query_tasks 返回附 `{budgets:{...}, breaker:frozen}`。

- [ ] 测试先红（含 Review Focus 4 文案断言）→ 绿 → commit `feat(guard): dispatch and question budgets`。

### Task B3: 结果判定（事件驱动两级）

**Files:** Create `src/host/guard/adjudicator.ts`；Modify `src/host/bridge/sessions.ts`（turn-end 事件接 adjudicator，依 S1 结论选源）、`src/host/memory/adapter.ts`（judgeOutcome 摘要面：输入会话尾部事件，输出 `{verdict:'completed'|'partial'|'failed', summary}`）、`src/shared/types.ts`（TaskResult 增 `deliveryOrigin:'worker'|'system-judged'`）；Test `tests/guard-adjudicator.spec.ts`。

**Interfaces:** `class OutcomeAdjudicator { onTurnEnd(sessionId): void; onFirstResponseTimeout(taskId); onWallClock(taskId) }`——守卫：任务属 dispatched|running、无已认领待答问题、本任务本周期未提醒过。第一级：`injectClosurePrompt(sessionId, taskId)`（requestId=`closure-${taskId}-${seq}` 幂等，文案照规格）；第二级：judgeOutcome 三态——completed→core 以判定摘要 completeTask（deliveryOrigin='system-judged'）+ 完成卡；partial|failed→blocked 附判定 + 异常卡；全过程写 progress 与项目记忆 `[事实]` 事故条目。兜底定时器：派发后 10min 无首响、墙钟 30min（Config：firstResponseTimeoutMs/adjudicationWallClockMs）。

- [ ] 测试先红（Review Focus 2/3 全覆盖：waiting-user 豁免、幂等、三态落位、判定交付标记、定时器兜底）→ 绿 → commit `feat(guard): outcome adjudication`。

### Task B4: 控制路由 + 紧急暂停
