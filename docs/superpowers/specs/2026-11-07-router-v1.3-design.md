# dsh-router v1.3 设计规格：分叉创建 worker 与身份卡协议（待终审）

> 前置：v1.2（main @ 3bac102）。来源：2026-11-07 与用户确认的优化方向（创建
> worker 时原样携带来源会话历史、利用前缀缓存）+ 用户补充（切换卡重申工具
> 范围）。取证：`docs/research/r10-fork-seed.md`（分叉宿主面）、
> `docs/research/r11-cache-observability.md`（缓存观测面）。
> 原则：**身份进历史不进系统提示词；前缀逐字节一致才有缓存；工具真闸永远
> 在执行层。**

## 1. 双模式（配置项 `workerSpawnMode`，默认 `cache-priority`）

| | 缓存优先（默认） | 最小面 |
|---|---|---|
| 三预设组合 | **完全统一**：同一段身份中立 complete persona + 同一套工具超集 | 维持现状（各预设最小工具白名单） |
| 分叉方式 | 宿主标准 `session/fork`（atSeq 缺省=最近完成轮前缀） | 插件复刻宿主分叉五步：`ctx.agents.create({sessionId, seed, inheritedEventCount, setup: worker 预设组合})`（`@deepseek-ai/dsh-session/fork` 的 buildForkSeed 可用，r10 §2/§5） |
| 系统提示词前缀 | 与来源会话逐字节一致 → **来源缓存全命中，只算新尾巴** | 与来源不同 → 缓存断裂（历史仍原样继承，价值=上下文完整） |
| worker 模型 | **继承来源会话模型**（分叉重放 model/selection，r10 §3）；类型 `models` 仅作展示与手动切换建议——切模型即换缓存，如实标注 | 创建后按类型 `models[0]` 钉模型（既有 selectModel 路径） |
| 角色安全 | 模型可见全部工具；身份卡声明授权范围 + **执行层 assertCallerRole 硬闸不变**（本就是真闸） | 同左，工具面更小 |

两模式切换是配置级（设置页 + root-config volatile），存量任务/会话不受影响。

## 2. 身份中立统一提示词 + 身份卡协议

1. **统一 persona**（缓存优先模式的三预设共用，complete）：写通用纪律（任务书
   协议、完成协议 complete_task/report_blocker、提问纪律、用户非执行器、冻结
   语义）+ **身份卡协议**：「每个会话历史中存在身份卡：`【身份卡】你是 …`。
   当前身份 = 历史中最后一张身份卡；`【身份切换卡】`由系统投递，权威最高。
   身份卡声明本身份可用的工具范围；范围外的调用会被系统拒绝——不要尝试。」
2. **Router 会话创建**即注入首条消息：`【身份卡】你是 Router…（职责与工具范围）`。
3. **切换卡三件套**（用户确认的强调点）：分叉创建 worker 后投递的第一条消息
   `【身份切换卡】你现在是 <类型名> worker：①身份与职责（**=该类型的系统
   提示词**——缓存优先模式下 persona 统一身份中立，类型提示词的生效位置
   从预设 persona 移到此处）；②**本身份可用工具清单（逐一列名）**与禁用
   提醒；③任务书全文（现行 v1 格式）`。主管分叉 worker 同路径同格式。
   类型的创建/列举工具（`create_worker_type`/`list_worker_types`，v1.1 起）
   与提示词指引（无合适类型先建再派）保持不变；类型 `models` 在缓存优先
   模式下仅展示（§1）。
4. 最小面模式沿用现行 persona 分置 + 切换卡简化版（无工具重申必要，仍带身份
   声明保持协议一致）。

## 3. 分叉创建 worker（替换现行 dispatchTask 的会话创建段）

1. 缓存优先：`session/fork {sessionId: 来源会话}`（来源=Router 或主管会话；
   atSeq 缺省）→ 子会话归组同 workspace（forkWorkspace 自动沿源，r10 §6）→
   改名 `类型名 · T-xxx 任务名`（rename 既有面）→ **不** selectModel →
   queue 投递切换卡+任务书（requestId=`switch-${taskId}-v${docVersion}`，
   写前意图账沿用）。
2. 最小面：复刻五步（新 sessionId、buildForkSeed(来源)、inheritedEventCount、
   worker 预设 setup、创建）→ attach workspace → rename → selectModel(类型
   models[0]) → 同款投递。
3. 既有失败语义全部沿用（分类/熔断/预算/重试上限/收尾判定）：分叉创建失败
   计 infra；切换卡投递走收尾提醒同款四码分治。
4. 子代理通道（主管的一次性子代理）不改建路径，仅在提示词中与分叉通道的
   选择准则并列（轻→子代理，重/持久→分叉 worker）。
5. 桌面版 fork meta 不写 parentSession（r10 §5）：任务谱系以账本 parentId
   为准（本就是权威），不受影响。

## 4. 缓存观测与验收（r11）

1. 观测面：根作用域 `session/event` 过滤分叉会话**第一条** assistant/message
   的 `data.usage.cacheReadTokens`。
2. state 暴露：TaskCard 增 `firstRequestCacheReadTokens?`（首请求命中量），
   完成卡摘要可选带「首请求缓存命中 X tok」。
3. 降级：适配器不回缓存字段（自定义网关）→ 如实显示「未上报」。
4. 验收：缓存优先模式下，从有若干轮历史的 Router 分叉 worker，首请求
   cacheReadTokens > 0（真实模型环境实测）；最小面模式同操作命中=0（断言
   缓存确实按设计断裂）；执行层硬闸在缓存优先模式下拦截越权工具调用（用
   worker 会话调 dispatch_task 被拒）。

## 5. 范围外

模型/成本硬预算、跨供应商缓存、验收流接线、身份卡的多级嵌套优化（主管
再分叉的卡片叠加语义只按「最新卡生效」处理，不做卡片树）。

## 6. 风险与回退

- 统一工具超集让模型看见越多越易试错 → 执行层硬闸 + 身份卡重申 + 越权
  拒绝的错误信息教育性文案；实测若 router 误用执行工具率显著上升，回退
  默认为最小面模式（配置一行）。
- fork 语义随宿主演进变化（atSeq/归组）→ 双版本取证已入 docs/research，
  升级核查清单补「fork 面回归」项。
