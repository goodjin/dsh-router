# dsh-router v1.1 设计规格（已批准）

> 前置：`2026-11-07-router-v1-design.md`（v1 已实现并上线）。本规格是 v1.1 增量，
> 来源为三部分：① 2026-11-07 与用户确认的功能需求（入口/类型管理/提示词编辑/
> 浮窗联动/样式）；② v1 首次真实运行排障结论（见 §2，证据存于会话日志与
> `~/.dsh/router/ledger.json` 现场）；③ 用户追加的派发策略（Router 可直派
> worker、主管可派子代理）。冲突时以本文档为准。

## 1. 目标

让「一个简单任务」走完理想路径：**Router 直接派 1 个 worker → worker 执行 →
complete_task → 结果入记忆**——全程无主管链、无空壳任务、无多余提问；同时把
worker 类型、提示词、默认模型变成界面可管理的实体。

## 2. P0 缺陷修复（先行，不做则其余无法验证）

1. **fs-search 行配置**：v1 worker 预设的 `@deepseek-ai/dsh-tool-fs-search`
   行缺必填 `sampleOverCapGlobResults`（宿主必填无默认，宿主自带预设传
   `false`），导致**所有 worker 会话创建失败**。修复：照宿主同款行补齐，并以
   宿主 standard/minimal 预设为基准**逐行审计本包全部预设子行的 config**，
   差异清单落测试。
2. **子行校验双轨修复**：v1 自建离线核查器对 config-less 子行未做包 Config
   校验，漏掉上颗雷。修复：离线核查器管静态 yml（任何子行含无 config 行都过
   包 Config 校验，用本案例写失败测试钉住）；**动态注册行**由插件在注册时用
   同一套校验函数把关（离线脚本碰不到运行时行）。
3. **工具输出 lossless-JSON 门禁**：`query_tasks` 曾返回非无损 JSON 致主管
   全盲。全部八件套工具（含新增工具）的输出值加序列化门禁测试；CI 先红后绿。
4. **派发失败不留空壳**：会话创建/投递失败时任务回到 `draft`（错误原因记入
   该任务 progress 字段），不产生「cancelled + 无会话」残留；同一任务连续派
   发失败达上限（默认 3）→ 自动 `blocked` 并通知 Router，禁止无限重试换模板
   碰运气。
5. **templateId 收紧**：dispatch_task 执行时校验 templateId 对当前启用类型
   列表（工具描述内嵌当前清单，注册类型变更时刷新），错误信息保持可用清单
   提示；杜绝 `general` 式幻觉。

## 3. 派发策略与行为护栏

1. **Router 自主决定层级**：简单单步任务**直接派 worker**（不升主管）；
   多步/需协调/有依赖拆分才派主管；无需执行的事实性问题**直接回答**（见下）。
   Router 提示词与 dispatch_task 描述同步写明决策准则。
2. **直接回答路径**：用户问题若已有信息可答（记忆/上下文/常识），Router 直接
   回答，不建任务、不派发；不确定是否需要执行时，先澄清再决定。
3. **主管双通道**：主管可派 **worker 会话**（持久、可交互、入账本）与
   **子代理**（一次性、进程内、不入账本、不开标签、不向用户提问）。简单
   子任务（只读查询、单点小改、格式转换）→ 子代理；需要多轮/提问/持久产
   品 → worker。子代理行按 r6 取证固定：`tool-subagent-control` 裸行 +
   `tool-subagent`（`provider: spawn`，`maxDepth: 2`）；**禁挂已删的
   `./list-agents` 子路径行，禁写跨版本死键**（modelSelectionSettings /
   modelSelection / modelDiscovery / backgroundMode）；主管提示词不硬依赖
   0.2.1 上不存在的 `list_agents`。
4. **禁止主管链**：主管之下只能派 worker 或子代理，禁止 supervisor→
   supervisor（dispatchGuard 加角色约束，执行时校验，非仅提示词）。
5. **用户不是执行器**（提示词 + 工具错误文案双管）：任何角色不得要求用户
   运行命令、粘贴输出、报告系统状态。工具不足或查询失败 → `report_blocker`，
   不得转为提问。
6. **提问纪律**：每任务澄清提问预算默认 **2 批**（可配置），由问答桥认领层
   强制：超预算的提问被拒并自动回一条「预算已用尽，请基于任务书做合理假设
   继续或 report_blocker」的回答；一次批量问完；禁止重复问已回答的问题；
   浮窗自定义文本回答必须端到端完整送达（补集成测试 + 现场验证），自定义
   输入框视觉上与选项区分明显。
7. **空壳清理**：cancelled/failed 且无会话的任务自动移出标签条与活动账本
   快照（保留归档记录可查）。

## 4. Router 入口与唯一性

- 入口：宿主新建会话的**预设选择器**选「Router」；若该项目已有 Router 会话，
  自动归档新建的空会话并跳转既有会话（宿主无创建前拦截钩子，事后归档+跳转
  是既定实现方式）。创建/复用时**置顶**（宿主原生 pin，用户可手动取消）。
- v1 的侧栏底部按钮保留为次要入口（自带去重）。

## 5. Worker 类型体系（动态预设）

- 类型字段：名称、描述、角色（worker/supervisor，默认 worker）、**允许模型
  列表**（有序；首个为该类型会话默认模型，其余为候选，不硬限制宿主选择器）、
  系统提示词、**初始技能**（从已装技能包勾选，预设内真实挂载）、启用状态、
  来源（手动 / Router 创建）。
- 每个启用类型运行时注册真实代理预设 `dsh-router-worker-<类型>`：persona
  （该类型提示词）+ 默认模型行 + 技能行 + 按角色的工具白名单 + 压缩组。
  **动态组合的每个宿主工具行必须带宿主要求的完整 config**（§2-1 教训），
  注册时过子行校验。
- 内置「通用 worker」类型（固定、不可删）继承 v1 静态 worker 预设（修复后），
  保证任何情况下可派发。Router 预设改为动态注册（id 不变 `dsh-router`），
  默认提示词/默认模型来自设置；注册失败回退静态定义。主管预设保持静态。
- 会话标题 = `类型名 · T-xxx 任务名`。
- **禁用 = 保留预设注册 + 拒绝新派发**（已关闭的该类型会话仍可重开——注销
  会使已关闭会话无法重开，r4 取证）；**删除 = 注销 + 明确提示「已关闭的该
  类型会话将无法重开，重建同名类型可恢复」**；活跃会话两者均不受影响。
- **默认模型钉法（r4 修正）**：`agent-default-model` 行挂进预设改不了主会话
  默认模型（宿主控制器在根上下文读取）。实施时做有界探查：会话创建后能否
  经宿主 API 设置该会话模型（界面可切必有通路）；可行则创建后即设默认；
  不可行则降级——类型仅记录模型清单（候选+展示），创建时不钉，会话内手动
  切换，设置页如实标注。
- 类型启用变更后宿主侧花名册即时可见；浏览器预设选择器的刷新节奏归宿主
  （我们的程序化派发不依赖选择器）。
- Router 工具新增：`list_worker_types`（全类型清单含启用态）、
  `create_worker_type`（现场建类型，即刻可用；只能创建，不能改删用户手动
  创建的类型）。

## 6. 设置页「Router 管理」栏目

- Worker 类型列表：新建/编辑/禁用/启用/删除；表单含 §5 全部字段（模型从宿主
  可用模型选取排序，技能从已装技能包勾选）。
- Router 默认：默认系统提示词（多行）、默认模型。
- 存储在宿主数据目录 JSON，经插件路由读写；v1 配置文件模板首启种子化导入
  一次后退役。

## 7. Router 会话内编辑系统提示词

- 「对话/轨迹」视图标签排注册第三视图**「系统提示词」**（宿主视图列表增量
  注册；先行验证标签自动出现，失败回退：会话头部编辑按钮）。
- 仅 Router 会话显示；默认值 = 创建时默认提示词；保存后下一轮生效；每项目
  会话互相独立。

## 8. 问题浮窗联动与返回

- 问题 chip 点击 = 展开小窗 **+ 自动切换到该 worker 标签**（在 worker 上下文
  中作答）；小窗为全局浮层，切换后仍悬浮；提交成功后消失，停留在 worker
  标签。
- worker/主管会话**右上角浮动「返回 Router」按钮**；Router 会话不显示。

## 9. 样式

- 本插件全部 UI：悬浮提示浅色浮层（禁黑底）；hover 反馈统一为颜色稍变深。

## 10. 先行可行性验证（实施第一步）

1. 动态预设注册/撤下（花名册即时可见、组合真生效、撤下不影响已建会话、
   注册时子行校验拦截坏行）。
2. 第三视图标签注册（对话/轨迹旁自动出现）。
3. 子代理工具行在双宿主的正确挂法（主包行；CLI 0.2.1-rc.2 与桌面
   0.2.2-rc.1 都绿）。

任一失败 → 回退方案回来重新确认。

## 11. 范围外（记录不做）

验收流接线（supervisor/user 策略，dispatch 仍固定 auto）、设置写通道之外的
宿主设置接管、模型硬限制、历史会话记忆回扫、chat-power 单条标签栏合并、
GitHub 远程与 web 安装验证。

## 12. 验收标准

1. 同一「数插件」任务：**1 条任务、1 个 worker 会话、0 主管、0 提问、无空壳**，
   完成后结果入记忆、标签条无残留。
2. 主管派子代理完成简单子任务：无新会话、无新标签、主管汇总后 complete_task。
3. 预设选择器新建 Router → 已有时自动跳转；Router 会话置顶。
4. 设置页 CRUD 全链可用；新建类型即可派发；禁用后派发被拒且报因。
5. Router 会话内可改提示词并下轮生效；worker 会话无此标签。
6. 问题 chip 点击切到 worker 标签；浮窗可答；答后消失；返回按钮回 Router。
7. 全部静态子行过双宿主离线核查；动态注册行过插件内注册校验测试；三门禁全绿。
