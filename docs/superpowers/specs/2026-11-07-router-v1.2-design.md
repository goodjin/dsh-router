# dsh-router v1.2 设计规格：失控防护层（已批准方向，待终审）

> 前置：v1.1 规格（功能层）已实现。本规格是**防护层**，来源：v1 事故系统复盘
> （`2026-11-07-router-v1-design.md` 时代的现场证据 + v1.1 排障结论）与用户两轮
> 修正（每消息一任务、失败才限流、事件驱动判定、完成卡人工核验）。
> 原则：**基础设施故障系统兜底，任务级失败模型处理，失控时用户一键刹车；
> 事件驱动优先于轮询与定时。**

## 1. 故障分类器

- 派发链路失败分两类：**infra**（会话创建失败、预设挂载失败、任务书投递失败）
  与 **task**（参数/校验/依赖类拒绝）。
- infra 失败**不进任务重试预算**（不换模板硬撞），直接计入熔断器计数并通知
  Router「系统故障，停止重试」；task 失败走既有 per-task 重试（3 次封顶）。
- 分类实现于 dispatchTask 失败路径，错误码带 `class: 'infra'|'task'`。

## 2. 全局熔断器（DispatchCircuitBreaker）

- 触发（滑动窗 10 分钟，两项任一）：
  a. infra 失败 ≥3 次；b. 创建任务 ≥10 个且零完成（纯创建风暴信号；阈值
  取高避免误伤主管合法并行拆解，误报代价 = 用户一键解除）。
- 冻结语义：一切 dispatch_task / create_worker_type 被拒，错误信息明确告知
  「派发已冻结（原因），请停止重试并向用户报告」；同时弹出异常卡。
- 解除：仅用户可解除（完成卡通道的异常卡上「解除冻结」按钮，或紧急暂停
  面板）；宿主重启后熔断状态持久化恢复。

## 3. 派发预算与限流

- **每条用户消息最多 1 个任务（硬限）**：Router 的定位是意图理解、澄清、分派；
  拆解归主管。要派第二个任务必须先 ask_user 列出计划与理由，用户确认后该
  消息的预算清零重计（确认视为新指令）。
- **Router 提问预算**：每条用户消息 1 批澄清（与任务预算共享确认语义）。
- **主管失败预算**：连续 3 次派发失败（infra 或 task 均计）→ 该主管的派发
  冻结、必须 report_blocker 上报；**成功子任务不设上限**（任务需求各异）。
- 预算状态对模型可见（query_tasks 返回中带当前预算与冻结态）。

## 4. 结果判定机制（事件驱动，两级）

**触发（第一时刻，不等定时）**：任务会话本轮结束（运行→空闲，无待决工具
调用）且任务仍处 `dispatched|running` 且**无已认领待答问题**（waiting-user
豁免——提问后轮次结束是正常形态）→ 立即进入：

- **第一级·收尾提醒**：向该会话注入一条收尾提示（「你已结束输出但未交付：
  请调用 complete_task 提交，或 report_blocker 说明阻塞，或说明剩余工作」）。
- **第二级·独立总结判定**：提醒轮结束仍无交付 → 系统对该会话输出做独立
  总结（用记忆摘要的 llm 通道），判定三态：
  - **实际已完成**（没调工具但活干完了）→ 以判定摘要自动落 result.md、
    任务 completed，**标注「系统判定交付」**，完成卡可退回；
  - **部分完成** → blocked（附判定与剩余工作），异常卡；
  - **失败** → blocked（附原因），异常卡。
- **兜底定时器**（防事件不来：派发后 10 分钟无首轮响应；任务墙钟 30 分钟
  可配）→ 走同一判定通道。
- 判定与提醒全部写入任务 progress 与项目记忆（事故条目，`[事实]`）。

## 5. 通知与用户控制

- **统一卡片通道**（复用问题浮窗视觉，非阻塞）：
  - **完成卡**：任务完成/系统判定交付时弹出——任务名、结果摘要、动作：
    「打开会话」「查看结果文档」「退回重做」（任务回 running + 自动
    supplement 判定意见）。人工核验「是否真完成」的正式入口。
  - **异常卡**：停滞判定、blocked、冻结、失败预算触顶——带对应动作
    （「解除冻结」「重派」「取消」）。
- **任务卡控制**：工作台任务行加 暂停/取消/重派 按钮（宿主侧补
  `POST /router/tasks/:id/control` 路由，语义与 control_task 工具一致）。
- **紧急暂停**：工作台顶部按钮 = 冻结派发 + 中断全部运行中任务会话
  （会话中断 API 先行取证，见 §7）+ 弹汇总卡。

## 6. 提示词与记忆增补

- Router/主管提示词补：infra 类错误一律停止重试并报告；收到冻结/预算拒绝
  的正确行为；blocked 任务「修因或取消」，禁止换任务名重派规避。
- 事故（infra 故障、超时、判定失败、退回重做）写入项目记忆 `[事实]` 条目
  （含原因与处置），供后续派发前检索。

## 7. 先行验证（实施第一步）

1. **turn-end 可观测性**：`api-session/status` running→false 与会话日志
   `turn/end` 事件的可靠性与时序（判定触发的数据源，二选一或并用）。
2. **会话中断 API**：宿主对独立根会话的中断/停止面（紧急暂停用；r2 的
   interrupt 语义仅限子代理，需另证）。
3. **收尾提醒注入**：对空闲任务会话 queue 一条用户消息唤醒下一轮的可行性
   （应即 sessionController.prompt 既有能力，确认无坑）。

## 8. 范围外

验收流完整接线（supervisor/user 策略）、模型/成本硬预算、Web 安装验证。

## 9. 验收标准

1. 模拟 infra 失败（改坏一个类型的预设行）→ 第 3 次失败即全局冻结，
   Router 派发被拒且错误信息明确；用户解除后恢复。
2. worker 干完活不调 complete_task → 本轮结束立即收到收尾提醒；仍不交付
   → 独立判定三态各自落位；判定完成卡「退回重做」全链可用。
3. 一条消息派第二个任务被硬拦，ask_user 确认后放行。
4. 主管连续 3 次派发失败被冻结且必须上报；成功子任务无上限。
5. waiting-user 任务轮次结束不触发判定。
6. 三门禁 + 双宿主两道核查全绿；临时实例实机回归 v1.1 验收项不回退。
