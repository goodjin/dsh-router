## §1 目标与定位

一个长期在线的任务编排插件（`@goodjin2/dsh-router`，独立仓库，不依赖本容器
其他插件）：

- 用户始终与 **Router 会话**交流；Router 理解需求、澄清、整理任务并派发。
- 真正的工作由**独立的 worker 会话**完成；多个 worker 执行或等待用户回答时，
  Router 仍能继续接收新需求。
- 理想路径（简单任务）：**Router 直接派 1 个 worker → worker 执行 →
  complete_task → 结果入记忆**——无主管链、无空壳任务、无多余提问。
- 复杂任务：Router 派主管，主管拆解并派 worker / 子代理，逐层汇总交付。
- 失控时系统兜底（熔断、判定、预算），用户有一键刹车（作用域暂停）与自救
  入口（解除冻结），**任何防护机制不得把用户永久锁死**。

## §2 对象模型与角色

| 对象 | 职责 | 生命周期 |
|---|---|---|
| Router 会话 | 与用户交流、整理任务、派发、汇报状态 | 长期存在，左侧常驻 |
| 任务 | 目标、约束、验收、状态、关联会话 | 提出 → 完成/取消，归档可检索 |
| Worker 会话 | 接受任务、执行、提问、交付 | 独立持久会话，左侧常驻，可再打开 |

- **角色**（权限维度）：`router` / `supervisor`（主管型）/ `worker`（工作型）。
  **Router 身份由预设 persona 直定**（2026-11-09 裁定：Router 是长期会话，不把
  身份钉进历史，不投身份卡）；身份卡只用于接收任务的 worker/supervisor（§11.2）。
- **专业类型**（配置维度）：编码、调研、文档、测试、审查……即 worker 模板（§10）。
- 主管可派 worker 与子代理；**禁止 supervisor → supervisor**（执行层校验，
  非仅提示词）。工作型不可派发。
- **父子关系**（`parentId`，谁负责）与**依赖关系**（`dependsOn`，开始前需哪些
  交付物）严格分开。依赖图拒绝循环；**菱形依赖（D→B→A 且 D→C→A）不是循环**。
- **派发溯源**：每个任务落 `dispatchedBySessionId`（发起派发的会话 id，由宿主
  在派发唯一注入口记录，不信任模型自填的 parentId）。作用域暂停按它算派发树。
- 默认一个任务一个 worker 会话；同任务补充/返工投递给原 worker。
- Worker 停止生成 ≠ 任务完成；完成必须走 `complete_task` 协议（§7）。

## §3 任务生命周期（状态机）

状态：`draft / queued / dispatched / running / waiting-user / review-pending /
paused / blocked / completed / cancelled / failed`。终态（completed / cancelled /
failed）无出边。迁移表是闭包集合，表外一律非法并报错。

必须成立的迁移（需求级，逐条可测）：

| from | 必须有的出边 | 语义 |
|---|---|---|
| draft | queued, blocked, cancelled | 依赖满足入队；派发失败封顶 |
| queued | dispatched, blocked, cancelled | 派发；失败封顶 |
| dispatched | **running, completed, review-pending**, paused, blocked, failed, cancelled | 见下方 R-1 |
| running | waiting-user, blocked, paused, review-pending, completed, failed, cancelled | 正常执行面 |
| waiting-user | running, blocked, failed, cancelled | 回答后恢复 |
| blocked | running, failed, cancelled | 修因恢复或放弃 |
| paused | running, cancelled | 恢复或取消；**无 completed 出边**（迟到完成被拒） |
| review-pending | completed, cancelled | 验收通过/放弃；驳回返工是完成协议专属操作（→ running，不走表边） |

**R-1（修正条款）**：活着的任务常态是 `dispatched`（`running` 只在判定转执行、
恢复、驳回返工时出现）。worker 在 `dispatched` 上直接调用 `complete_task` 必须
能走通：auto 策略且无未结子任务 → `completed`，否则 → `review-pending`。
缺这两条边会造成「worker 永远交不了完成、账本 0 条 completed」的现场事故
（2026-11-08 账本复核证实），属于必须修复的需求，不是可选优化。

其余规则：

- 派发失败达 per-task 上限（默认 3）→ 自动 `blocked` 并通知 Router；错误原因
  记入该任务 progress；不产生「cancelled + 无会话」空壳。
- cancelled/failed 且无会话的任务自动移出标签条与活动账本快照（归档记录保留）。
- 暂停（手动 control_task 与作用域暂停同语义）适用于 `dispatched` / `running`；
  `waiting-user` 任务本就停着等用户，不需要暂停（可直接取消）。

## §4 入口与会话管理

### 4.1 创建入口

- 主入口：宿主新建会话的**预设选择器**选「Router」。创建时绑定当前项目工作
  目录，创建普通持久会话（左侧 Router 图标区分），默认打开 Router 视图，
  创建/收编时**置顶**（宿主原生 pin，用户可手动取消）。
- 次要入口：侧栏底部按钮（自带去重）。
- 一个项目可有多个 Router，共享项目记忆、各自管理任务树。

### 4.2 Router 会话独立性（v1.4 语义，替代 v1.1 的归档+跳转）

- **Router 会话全部独立**：不去重、不归档、不跳转、不复用。picker 每建一个
  Router 预设会话就是一个新 Router。
- **收编**只做一件事：把 picker 自建的 Router 预设会话登记进工作台
  （`ui.routerSessions`）。不再补发身份卡（2026-11-09 起 Router 撤卡，§2）。
- 判定源 = 受限会话头读取器 + 持久化增量索引（运行边界见 §16）；
  **稳态轮询零副作用**，不得全量重扫（2026-11-07 OOM 现场的教训）。
- 宿主归档的会话不登记、不投卡；本插件不做任何自动归档/撤销动作。

### 4.3 会话导航与焦点

- 两层导航：第一层（本插件）会话导航标签条切换 Router/worker；第二层
  （chat-power，若安装）当前会话内工具标签。职责边界：会话导航/任务树/
  问题汇聚归本插件；会话内文件/终端/浏览器归 chat-power；原生右侧栏归宿主。
  不安装 chat-power 时本插件独立可用；不直接操作 chat-power 内部状态。
- 新派发任务**不抢焦点**，默认保持 Router 为当前标签。
- 关闭 worker 标签只关视图，不停任务、不删左侧会话；左侧点击可重开。
- 完成任务保留会话与结果；标签可手动关闭。
- worker/主管会话右上角浮动「返回 Router」按钮；Router 会话不显示。
- 会话标题 = `类型名 · T-xxx 任务名`。

## §5 派发策略与预算

### 5.1 行为主线（2026-11-09 用户裁定，替代旧层级决策节）

每条用户消息按五步走（写进 Router 提示词）：

1. **判断意图**：无需执行的事实问题直接回答；信息不足先 ask_user 问清楚再派
   （宁可多问一句，不派错方向）；明确要执行才进入派发。
2. **判断所属项目与模块**：用户说清用用户的；没说清就对照上下文「项目列表」
   从需求关键词判断，`dispatch_task` 填 `project`（项目 id 或路径，执行层解析、
   匹配不到按项目清单拒绝）；判断不了再问。monorepo 的模块细分写进
   goal/constraints，不填子目录。
3. **选择执行方式**（从轻到重）：轻活（收尾快、不留持久产出）→ 一次性子代理，
   不建任务；简单任务（单步）→ worker；复杂任务（多步/协调/依赖拆分）→
   supervisor。选类型以 list_worker_types 为准，**没有合适类型就先
   create_worker_type 新建再派**，不硬塞不对口类型。
4. **派发**：goal/acceptance/constraints/materials 写自足无歧义；系统自动生成
   任务书文档，并给执行会话投「简洁任务分派 + 文档地址」（§6），全文 worker 自读。
5. **后续请求对照活动任务**：新消息先看「活动任务」快照——是某个在跑任务的
   补充/修正/追加材料 → `supplement_task` 追加，**不为后续新建任务**；全新工作
   才新派。
- 决策准则写进 Router 提示词与 dispatch_task 工具描述。

### 5.2 主管双通道

- **worker 会话**：持久、可交互、入账本（分叉创建，§11）。
- **子代理**：一次性、进程内、不入账本、不开标签、不向用户提问。
- 选择准则：轻（只读查询、单点小改、格式转换）→ 子代理；重/多轮/需提问/
  持久产品 → worker。子代理行挂法按取证固定（`tool-subagent-control` 裸行 +
  `tool-subagent` spawn，禁挂已删子路径行、禁写跨版本死键）。

### 5.3 预算（三层，互不替代）

| 层 | 限额 | 出路 |
|---|---|---|
| Router 每轮任务 | 每条用户消息最多 1 个任务（硬限） | 先 ask_user 列计划与理由，用户确认开启新轮、预算清零重计 |
| Router 每轮提问 | 每条用户消息 1 批澄清 | 与任务预算共享确认语义；超批被拒并自动回「请合并为一批重问」 |
| 主管失败预算 | 连续 3 次派发失败（infra/task 均计）→ 该主管派发冻结 | 必须 report_blocker 上报；**成功子任务不设上限** |
| 任务澄清预算 | 每任务默认 2 批（可配置），问答桥认领层强制 | 超预算自动回「预算已用尽，请基于任务书做合理假设继续或 report_blocker」 |
| per-task 重试 | 同一任务派发失败 3 次封顶 → blocked | 禁止无限重试换模板碰运气 |

- 预算状态对模型可见（query_tasks 返回带当前预算与冻结态）。
- supplement 重派与 dispatch 同口径受预算/冻结约束，不得绕过。

### 5.4 行为护栏（提示词 + 执行层双管）

- **用户不是执行器**：任何角色不得要求用户运行命令、粘贴输出、报告系统状态；
  工具不足或查询失败 → report_blocker，不得转为提问。
- 提问纪律：一次批量问完；禁止重复问已回答的问题。
- templateId 执行时校验对当前启用类型清单（工具描述内嵌清单，类型变更刷新）；
  错误信息带可用清单，杜绝幻觉类型。
- infra 类错误一律停止重试并报告；blocked 任务「修因或取消」，禁止换任务名
  重派规避。
- 修同一仓库的 worker 用独立 worktree 或串行；取消精确定位到任务。
- 主管递归派发受最大深度、并发（按 worker 类型上限排队）、任务数限制。

## §6 任务文档协议（派发即文档）

每个任务稳定 ID，目录 `tasks/<ID>/`：

```text
task.v1.md   原始任务书（不可变）
task.v2.md   补充要求后的新版本
progress.md  当前进展摘要（执行者更新）
result.md    最终交付报告（完成时生成）
```

- 任务书字段：目标/背景/范围、约束、验收条件、所属项目与工作目录、指派角色
  与专业类型、父任务与依赖任务、输入材料与交付物引用、来源会话与消息引用、
  文档版本。
- 派发流程：形成任务书 → 持久化版本 → 校验依赖与权限（含 project 解析，§5.1
  步骤 2）→ 投递**简洁任务分派**（ID/标题/目标/验收要点/约束 + 任务书文档地址；
  2026-11-09 裁定，替代「初始输入含任务书全文」——全文由 worker 按地址自读，
  Router 写的目标与验收必须自足）→ worker 接收。主管向下派发同协议；从最终
  结果可追溯到最初需求。补充要求升 docVersion；旧版本完成提交拒绝；补充重投
  同语义（升版简述 + 当前约束 + 新版本文档地址）。
- 文档管阅读/回溯/共享；运行状态/投递去重/依赖解锁由持久任务账本管
  （按 taskId+版本关联）。补充要求升 docVersion；旧版本完成提交拒绝。

## §7 完成与验收协议

### 7.1 complete_task = 申请交付

提交字段：任务 ID、执行版本（docVersion）、结果摘要、结果文档引用、交付物
引用、验收依据、遗留问题。

服务端校验（全部执行层强制）：

1. 调用者是当前任务执行者（会话归属校验）；
2. 针对当前有效执行版本（旧 worker 迟到提交拒绝，stale-version）；
3. 必填完整；
4. 主管任务无未结束必需子任务（有则进 review-pending 等子任务结清）；
5. 重复提交幂等去重（completed/review-pending 上同版本重提返回首次记录）。

失败或阻塞用 `report_blocker`，不得用完成工具掩盖。模型自然结束、空闲、
关标签都不算完成（走 §8 判定）。

### 7.2 验收策略（三态全部为现行需求）

| 策略 | 语义 |
|---|---|
| `auto`（默认） | 校验过且无未结子任务 → 直接 completed |
| `supervisor` | → review-pending，主管验收（accept）后 completed |
| `user` | → review-pending，Router 出验收卡，用户确认后 completed |

- 验收通过：review-pending → completed。驳回返工：review-pending → running，
  驳回意见落 progress（worker 第一眼可见），自动 supplement 给原 worker。
- **子任务结清重判**：父任务 review-pending 且子任务全部结清时，auto 语义的
  父任务自动转 completed（沿 parentId 级联，必终止于根），不得死锁。
- 完成被接受后由**服务端统一执行**：存 result.md、记忆更新、完成卡通知、
  通知上级、解锁依赖并自动派发、清理活动上下文——Router 不在生成也能推进。

## §8 结果判定（事件驱动，两级）

- **触发**：任务会话本轮结束（运行→空闲，无待决工具调用）且任务仍处
  `dispatched|running` 且无已认领待答问题（**waiting-user 豁免**）→ 立即判定，
  不等定时器。
- **第一级·收尾提醒**：向该会话注入收尾提示（请 complete_task / report_blocker /
  说明剩余工作）。
- **第二级·原会话自判**（2026-11-09 起替代独立总结判定）：提醒轮结束仍无交付
  → 向**同一执行会话**注入判定请求（只回一行 JSON 三态），下一轮结束解析其
  回复落位：
  - 实际已完成 → 自动落 result.md、completed，标注「系统判定交付」，完成卡可退回；
  - 部分完成 → blocked（附判定与剩余工作），异常卡；
  - 失败 → blocked（附原因），异常卡；
  - 回复缺失/不可解析/请求未被会话处理 → blocked「判定不可用」附实情。
  - 判定不再发起任何独立模型调用（不走 ctx.llm.stream 通道——该通道借别的
    会话路由、消息形状曾不合宿主契约，2026-11-09「判定模型返回空白」事故）。
- **兜底定时器**（防事件不来）：派发后 10 分钟无首轮响应；任务墙钟 30 分钟
  可配 → 同一判定入口。**到期先查会话运行态：仍在跑（模型请求未超时=还在
  等）就整体让位给「轮结束」事件路径**，不打扰、不另设重试定时器。
- 判定与提醒全部写入任务 progress；事故条目仅在记忆启用时写项目记忆（§12）。

## §9 失控防护

### 9.1 故障分类器

派发链路失败分两类，错误码带 `class`：

- **infra**：会话创建失败、预设挂载失败、任务书投递失败 → **不进任务重试
  预算**，计入熔断器并通知 Router「系统故障，停止重试」。
- **task**：参数/校验/依赖/预算类拒绝 → 走 per-task 重试（3 次封顶）。

### 9.2 全局熔断器（自动，且仅自动）

- 触发（滑动窗 10 分钟，任一）：infra 失败 ≥3 次；创建任务 ≥10 个且零完成
  （创建风暴，阈值取高避免误伤主管合法并行拆解）。
- 冻结语义：一切 dispatch_task / create_worker_type 被拒，错误信息明确
  「派发已冻结（原因），请停止重试并向用户报告」；同时弹异常卡。
- 持久化：宿主重启后恢复；并发首访装载不得丢增量。
- **解除仅用户可发起**，且入口必须真实可用：界面按 `RouterState.breaker`
  的真实冻结态显示「解除冻结」按钮（不得用「是否存在某张卡」推断——历史上
  那条路永远不出现按钮，用户被锁死）。
- **遗留标记作废**：装载时遇到 `reason === 'user-emergency'` 的冻结态直接
  丢弃并回写（旧版手动全局暂停的遗物，新版永不写它）；自动冻结原因照旧恢复。

### 9.3 作用域紧急暂停（用户一键刹车）

三条硬约束：

- **C1 作用域**：只停当前 Router 会话派出的活（沿 `dispatchedBySessionId` →
  执行会话闭包算派发树，含主管再拆的下游）；别的 Router 的任务不碰。
- **C2 无全局标记**：不写任何全局持久化状态；之后的新派发不受影响。
- **C3 不碰熔断**：全局熔断保持 §9.2 原样。

执行语义：

- 目标 = 派发树内 `status ∈ {dispatched, running}` 且有会话的任务。
- **两阶段**：先把所有目标落账本 `paused`，再统一中断会话（agents.cancel，
  原因留痕）。账本优先：paused 无 completed 出边，迟到的 complete_task 被
  状态机当场拒掉。落账本失败的任务不断其会话，逐任务如实上报。
- 恢复 = 既有 resume 路径（paused → running + 给执行会话投「已恢复」通知）。
- 通知：每个被暂停任务一张异常卡（打开会话/取消/知道了）；给当前 Router
  会话投一条告知（steer，只告知不硬拦）。**不写全局「派发已冻结」卡。**
- 路由 `POST /router/emergency-pause` 收 `{ routerSessionId }`（必填，校验是
  已登记 Router 会话，否则 400）；响应带逐任务结果（paused/interrupted/detail）
  与汇总（pausedCount/failedCount/notified）。
- 诚实边界：`dispatchedBySessionId` 只对启用本机制后派出的任务生效；旧账本
  行无法归属，不会被暂停（如实告知，不猜测）。

## §10 Worker 类型与预设

- 类型字段：名称、描述、角色（worker/supervisor，默认 worker）、允许模型列表
  （有序，首个为默认候选）、系统提示词、初始技能（已装技能包勾选、预设内
  真实挂载）、启用状态、来源（手动 / Router 创建）。
- 每个启用类型运行时注册真实代理预设 `dsh-router-worker-<类型>`：persona +
  默认模型行 + 技能行 + 按角色的工具白名单 + 压缩组。**动态组合的每个宿主
  工具行必须带宿主要求的完整 config**，注册时过子行校验（fs-search 缺
  `sampleOverCapGlobResults` 曾让所有 worker 建不出会话）。
- 内置「通用 worker」类型固定不可删，保证任何情况下可派发。Router 预设
  动态注册（id 不变 `dsh-router`），注册失败回退静态定义；主管预设静态。
- **禁用** = 保留预设注册 + 拒绝新派发（已关闭会话仍可重开）；**删除** =
  注销 + 明确提示「已关闭的该类型会话将无法重开，重建同名类型可恢复」。
  活跃会话两者均不受影响。
- 默认模型钉法按取证结论：能经宿主 API 创建后即设则设；不可行则降级为
  「类型仅记录模型清单（候选+展示），会话内手动切换」，设置页如实标注。
- Router 工具：`list_worker_types`（全清单含启用态）、`create_worker_type`
  （现场建类型即刻可用；只能创建，不能改删用户手动创建的类型）。
- 设置页「Router 管理」：类型 CRUD 表单（名称/描述/角色/模型/技能/启用；
  **不再收系统提示词**——新建不带提示词键即可建，宿主按角色补默认；编辑
  patch 不带提示词键，既有值含首尾空白逐字保留）；Router 默认模型（默认
  系统提示词的输入 UI 已移除，既有 routerSystemPrompt 数据保留，保存默认
  模型时原样带回）；存宿主数据目录 JSON 经插件路由读写。
- 会话内「系统提示词」视图（曾为 §10 的第三视图）已移除（2026-11）：不再
  注册 conversation.view 条目，会话内无提示词查看/编辑入口。底层既有提示词
  数据、会话覆盖存储与 `/router/prompt` 宿主路由、按角色默认与身份卡链路
  全部保留，不做清空或重置。

## §11 Worker 创建：分叉与身份卡

### 11.1 双模式（配置 `workerSpawnMode`，默认 `cache-priority`）

| | 缓存优先（默认） | 最小面 |
|---|---|---|
| 预设组合 | 三预设完全统一：身份中立 complete persona + 工具超集 | 各预设最小工具白名单 |
| 分叉 | 宿主标准 `session/fork`（atSeq 缺省） | 插件复刻宿主分叉五步（buildForkSeed + worker 预设 setup） |
| 前缀缓存 | 与来源逐字节一致 → 来源缓存全命中 | 缓存断裂（历史仍原样继承） |
| worker 模型 | 继承来源会话模型；类型 models 仅展示 | 创建后钉类型 models[0] |

- 角色安全两模式相同：模型可见工具 ≠ 可用工具，**执行层角色硬闸永远是真闸**
  （越权调用被拒，错误文案有教育性）。
- 模式切换是配置级（设置页 + root-config volatile），存量任务/会话不受影响。

### 11.2 身份卡协议（身份进历史，不进系统提示词；2026-11-09 起 Router 除外）

- **Router 会话不投身份卡**：Router 是长期会话，身份由预设 persona 直定（§2）；
  收编也不补卡。worker/supervisor 分叉后第一条消息 = `【身份切换卡】`两件套：
  ①身份与职责（= 该类型系统提示词，cache 优先模式下生效位置在此）+ 本身份
  可用工具清单与禁用提醒；②简洁任务分派（含任务书文档地址，§6）。主管分叉
  worker 同路径同格式；需要再派子 worker 时照旧走分叉复用。
- 创建流程：fork → 归组同 workspace → 改名 → （最小面才 selectModel）→
  queue 投递切换卡+任务书（requestId=`switch-${taskId}-v${docVersion}`，
  写前意图账）。失败语义沿用 §9（分叉失败计 infra；投递四码分治）。
- 子代理通道不改建路径。任务谱系以账本 parentId 为权威（fork meta 不写
  parentSession 不影响）。

### 11.3 缓存观测

- 观测分叉会话第一条 assistant/message 的 `cacheReadTokens`，落
  `TaskCard.firstRequestCacheReadTokens`（一次性语义，不覆盖）；完成卡摘要
  可选带「首请求缓存命中 X tok」；适配器未上报则如实不显示。

## §12 三层记忆

三层各是一份 Markdown（YAML 头 +「## 摘要」+「## 条目」），rootDir 由宿主
集成层配置：

| 层 | 文档 | 内容 |
|---|---|---|
| 会话摘要 | `sessions/<sessionId>.md` | 头部 `lastSummarizedSeq`（增量位）与 title；最近一次增量总结 |
| 项目记忆 | `project.md` | 项目约定、已确认事实、重要交付物（当前项目优先检索） |
| 全局记忆 | `global.md` | 明确长期偏好、跨项目约定 |

规则（全部执行层强制）：

- **总开关 `memoryEnabled`（2026-11-09 起默认 false）**：停用时后台增量摘要、
  完成记忆写入、事故写入、检索注入全部不接线（`search_history` 如实回
  「记忆服务未配置」）。重新启用前须把摘要改为原会话内进行（判定同款方向），
  且一次性提示词消息必须按宿主契约投喂（content 用文本块数组、系统提示词走
  `system` 字段——`toHostOneShotMessages` 是范本）。

- 条目追加式，锚点 e1/e2… 单调递增；字段：kind（[决定]/[建议]/[事实]）、正文、
  anchor、key、sources（来源会话#消息范围）、at、conflicts-with。
- 结论带来源引用；用户决定/worker 建议/已验证事实分别标记；**冲突保留不合成**
  （同主题重复指向旧锚 conflicts-with）。
- 低信息门：正文去空白不足 20 字符拒写。多行 key 必须扁平化，不得破坏文档结构。
- 增量摘要：只喂 lastSummarizedSeq 之后的事件；空增量跳过；llm 失败不推进位。
- 检索 `search(query, scope)`：关键词 AND（大小写不敏感、中文包含），按写入
  时间倒序最多 20 条，`memoryRef = memory://<文档>#<锚>`。
- 摘要用注入式 `llm.stream(messages, signal)`；记忆模块不 import 任何宿主包。
- 并发写串行化，不得互相覆盖；完成任务移出活动上下文但结果进记忆；事故
  （infra 故障、超时、判定失败、退回重做）写项目记忆 `[事实]`。
- 历史会话后台补建不阻塞接单。

## §13 Router 上下文管理

- 可查历史完整保留（会话日志）；**发给模型的上下文只含调度所需**：
  角色提示词 + **项目列表**（registry 投影，2026-11-09 行为主线步骤 2 的判定
  数据源，随快照缓存刷新）+ 未派发需求 + 全部未结束任务短卡（活动账本快照，
  即「当前在跑任务清单」——Router 据此判断新请求是否历史任务的后续）+ 本轮
  用户消息 + 未处理必要通知。
- 活动任务短卡字段：ID/标题、目标与关键验收、worker 类型/会话 ID、状态/一句话
  进度、依赖、待回答事项、最新补充约束。
- **每次成功转交后执行一次上下文整理**：存完整任务书 → 确认入箱 → 压缩相关
  讨论为短摘要 → 替换模型历史对应内容 → 后续状态更新覆盖卡片（不追加重复
  摘要）。摘要失败保留原上下文重试，禁止重复派发。
- 一条消息多需求：已派发部分可压缩，仍在澄清部分必须保留。
- 完成任务：存结果与交付记录 → 完成卡片 → 从下一轮活动上下文移除 → 交付物
  引用转移给后续任务 → 归档可检索；旧任务摘要同步退出模型历史。
- 未结束任务全保留；任务多时缩短卡片，不静默丢弃；活动容量可配置防撑爆窗口。
- 上下文整理期间新消息入队不丢。

## §14 界面需求

### 14.1 问题浮窗（Router 界面内）

- worker（含主管）提问汇聚到浮动卡片区，默认收起，显示任务名与问题摘要；
  展开支持单选/多选/自由文本；自定义输入框视觉上与选项区分明显。
- 问题 chip 点击 = 展开小窗 **+ 自动切换到该 worker 标签**；小窗全局浮层，
  切换后仍悬浮；提交成功消失，停留在 worker 标签。
- 提交后显示「正在送达」，服务端确认后消失；失败保留卡片与已填内容。
  自定义文本回答必须端到端完整送达。
- 收起不是回答；多 worker 问题分别排队互不覆盖。回答由插件直接送达对应
  worker，不经 Router 模型转述；Router 只收状态更新。

### 14.2 统一通知卡片通道（非阻塞）

- **完成卡**：任务完成/系统判定交付时弹出——任务名、结果摘要（可带缓存命中）、
  动作：打开会话 / 查看结果文档 / 退回重做（回 running + 自动 supplement 判定
  意见）。人工核验「是否真完成」的正式入口。
- **异常卡**：停滞判定、blocked、冻结、失败预算触顶、被暂停任务——带对应
  动作（解除冻结/重派/取消/打开会话/知道了）。
- 卡片动作幂等：提交中不重发；副作用不得放在 React setState 更新器内
  （StrictMode 双调用会重复提交）。
- 浮窗顶部两个按钮：**「暂停本 Router 任务」**（常驻，作用域暂停）；
  **「解除冻结」**（仅当真实熔断态 frozen 为真）。

### 14.3 工作台

- 任务行控制：暂停 / 取消 / 重派（`POST /router/tasks/:id/control`，语义与
  control_task 工具一致）。
- 任务树/状态/待答事项可见；Router 会话登记列表来自收编（§4.2）。
- **分派会话窗口**（2026-11-09 交互裁定）：按会话聚合分页展示本项目派出的
  会话（状态角标动画尊重系统减少动态效果设置）；**点击窗口 = 直接切换到该
  会话当当前会话**（与标签切换同一条 openSession 通道），卡片动作「打开会话」
  同样切换；右上角浮动「返回 Router」按钮即 §4.3 既有机制。不再有内嵌详情
  浮层（retain/embedded 那套已随交互简化移除）。

### 14.4 样式

- 全部 UI 悬浮提示用浅色浮层（禁黑底）；hover 反馈统一为颜色稍变深。

## §15 可靠性与持久化

- 派发幂等；账本、待答问题、会话入口、熔断态、判定索引全部持久化，重启恢复。
- 关视图/刷新浏览器不影响执行；Router 不等待 worker。
- 中断不伪装成功（标中断/待恢复）；并发受控（按 worker 类型上限排队）。
- 账本写并发安全：创建/升版/完成在锁内一致判定；持久化原子写；并发首访装载
  去重；同任务补充/解锁共用任务锁不重复派发。
- 会话收编索引的单调屏障（代际/权威 token/授予代数）在会话消失时随索引一起
  清理，不得泄漏或误清新实例。
- 宿主 HTTP 路由：请求体必须是 JSON 对象（否则 400）；500 错误对外只报
  `internal error`，不泄漏路径与内部细节。

## §16 收编运行边界与诊断（需求摘要）

细节以 `docs/router-adoption-operations.md` 为准，需求级约束：

- 判定不调用宿主整日志重放；冷盘有界 stable-EOF 扫描（默认上限：输入
  256 KiB / 解压 1 MiB / 4096 行 / 单行 64 KiB / 2 秒生命周期）；live 会话走
  投影与事件直达判定（零盘读）。
- `/router/state` 轮询（2.5 秒）只消费增量授予与定点核验；单轮预算同时约束
  维护与副作用；延期重试（指数退避 2s→60s，到期最小堆）与新授予轮转交替，
  失败候选**可恢复**、不永久放弃；稳态零副作用、不遍历宿主成员全集。
- 每个副作用启动前与登记等待后都复核权威事实（判定/成员/归档/新鲜度/代际）；
  单候选失败不阻断邻居；unknown 只跳过自身，不挡整个工作区。
- `GET /router/health` 零盘 IO 自报诊断（索引计数、收编轮次、延期分布、授予
  面、预算耗尽计数）；不返回会话正文/标题/路径。

## §17 打包、装载与门禁

- 浏览器半边三条件：`dsh.bundle.patch` 声明、`dsh.client.platform = "web"`、
  装载行 name 为裸包名。`exports["./client"]` 只写字符串或 `{default: 字符串}`；
  `lib/client.js` 为单文件 CJS 工厂（ModuleLoader 包裹，顶层无 import/export）；
  `.` 入口指向宿主侧入口，浏览器代码不进宿主进程。装载接线测试钉住全部条款。
- 门禁三条全绿：typecheck / test / build；产物（dist/entry.js、lib/client.js 及
  宿主自包含入口）入库、改源码必重建、构建字节可复现；仅跟踪文件的干净安装
  加载测试过。
- 预设/声明行改动后跑容器核查脚本，**双宿主都绿**；动态注册行过插件内注册
  校验；全部编排工具输出过 lossless-JSON 序列化门禁。
- 离线门禁不能替代真实桌面验证；不自动重启正在运行的桌面版。

## §18 范围外（记录不做）

模板可视化编辑器（设置页表单之外）、导出分享打包、多 Router 协同、记忆向量
检索、chat-power 单条标签栏合并、模型/成本硬预算、跨供应商缓存、身份卡多级
嵌套优化（最新卡生效即可）、web profile 安装验证（发布流程另行）。

## §19 验收标准

1. 简单任务理想路径：1 条任务、1 个 worker 会话、0 主管、0 提问、无空壳；
   完成后结果入记忆、标签条无残留。
2. 连续提多个需求，Router 持续分派不阻塞、不抢焦点；一条消息第二个任务被
   硬拦，ask_user 确认后放行。
3. worker 在 dispatched 上直接 complete_task 能完成（R-1）；关标签/刷新不
   影响执行；重启后任务关系与待答问题恢复。
4. worker 提问集中浮现；chip 点击切 worker 标签；答后消失继续执行；自定义
   文本完整送达；返回按钮回 Router。
5. 主管派子代理完成简单子任务（无新会话/标签）；主管派 worker 按依赖启动；
   supervisor→supervisor 被拒；工作型无派发工具；越权工具调用被执行层拒绝。
6. 三态验收各自落位；驳回返工全链可用；子任务结清父任务不死锁。
7. worker 干完不调工具 → 收尾提醒 → 独立判定三态落位；判定完成卡可退回；
   waiting-user 轮次结束不触发判定。
8. infra 失败第 3 次全局冻结、错误信息明确；用户按真实冻结态解除后恢复；
   遗留 user-emergency 标记重启即作废。
9. 作用域暂停只停当前 Router 派发树（含下游），逐任务如实上报；paused 拒
   迟到完成；resume 恢复；其他 Router 与新派发不受影响。
10. 缓存优先模式分叉首请求 cacheReadTokens > 0（真实模型实测）；最小面模式
    命中 = 0；身份卡/切换卡协议端到端可见。
11. 收编稳态零副作用（CPU/内存平稳）；picker 新建 Router 被登记并幂等收到
    身份卡；健康诊断字段齐全。
12. 门禁三条全绿 + 双宿主核查绿 + 干净安装加载测试过。
